# 대표 메뉴 카탈로그와 편집 기준

버전: v0.1.1 · 조사/편집: 2026-10-17

음식 460개, 카페 170개, 총 630개. 음식은 점심 425개/저녁 455개 후보다. 목록은 `assets/js/data/catalog.js`가 원본이며, 앱은 이 목록 전체에서 모드·카테고리 조건을 적용해 추첨한다.

## 이름을 저장하는 기준

- 브랜드명, 지역명, 온도, 사이즈, 매운 단계, 원산지·프리미엄 수식어, 토핑만 붙인 이름을 무한히 생성하지 않는다.
- 곱창전골은 곱창전골로 저장한다. 깻잎곱창전골·한우곱창전골 같은 변형을 별도 추첨 후보로 늘리지 않는다.
- 닭발과 무뼈닭발은 먹는 형태가 다르므로 별도 메뉴로 유지한다. 조리법·주재료·먹는 방식이 달라 통상 독립 메뉴로 주문하는 종류는 구분할 수 있다.
- 같은 음식의 별칭/다른 표기는 하나로 합친다. 예: 빈대떡→녹두전, 더치라테→콜드브루 라테, 레모네이드→레몬 에이드, 브레첼→프레첼, 찰깨빵→깨찰빵.
- 크기만 다른 꼬마김밥은 김밥으로, 포크커틀릿은 돈카츠로, 수육국밥은 돼지국밥으로 정리한다.
- 사케동은 연어덮밥, 돈까스는 돈카츠로 대표 표기를 정한다. 추가 수록 시 두 이름을 중복 등록하지 않는다.
- HOT/ICE, 사이즈, 지역·매장별 이름은 별도 후보로 만들지 않는다. 시즌 한정·브랜드 고유 상품명도 대표적인 종류로 정리한다.
- 상위 개념만으로 중복될 수 있는 메뉴는 정리한다. 예: 만두 대신 군만두/찐만두/물만두, 마르게리타 피자 등 세부 토핑 피자는 피자로 통합한다.
- 대표 메뉴 여부는 편집 판단이며 자동 문자열 유사도만으로 다른 음식을 합치지 않는다. 지역성과 구입 가능성은 사용자의 위치에 따라 달라질 수 있다.
- 한식/중식/일식 등은 추천 편의를 위한 대표 분류 하나이며 음식의 유일한 기원을 단정하지 않는다. 퓨전 음식은 한 분류에서만 추첨한다.
- 단품, 공유 요리, 간편식·간식까지 포함한다. 영양학적 한 끼의 완전성을 보장하는 분류가 아니다.

## 유지보수

카탈로그의 배열 위치 대신 정규화된 대표 이름을 ID로 사용한다. 새 메뉴를 중간에 추가하거나 정렬해도 기존 메뉴 ID가 이동하지 않는다. 기존 v0.1 설정에는 메뉴 ID/결과가 저장되지 않아 설정 마이그레이션은 필요하지 않다. 이름 자체를 바꾸는 경우 향후 후보 저장 기능(v0.2)을 추가할 때 별칭/ID 이전 정책이 필요하다.
